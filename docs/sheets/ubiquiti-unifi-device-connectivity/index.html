Ubiquiti UniFi device connectivity cheat sheet

Follow adoption and management connectivity through the UniFi console.

UniFi Network application; excludes EdgeOS and airMAX CLI.

Walkthrough

Use access to the correct UniFi site. Menu labels depend on the Network release. Avoid readopting or resetting devices while collecting evidence.

Step 1: Locate the affected device

UniFi Network → Devices

Confirm the site, MAC address, model and displayed status. An offline device may still be forwarding traffic while its management path is unavailable.

Step 2: Inspect the management path

Device details → IP address and uplink

Compare management IP, VLAN and upstream port with the intended topology. An APIPA address indicates that the device did not obtain the expected DHCP address.

Step 3: Review VLAN and link settings

Upstream switch → Ports → Port Manager

Compare native and tagged networks on the uplink with the management VLAN. Inspect settings without applying a new port profile during diagnosis.

Step 4: Validate the management dependency

Check console reachability and required ports

Use the official UniFi required-ports reference for your deployment. Test only relevant paths; do not broadly open inter-VLAN traffic to make adoption work.

Step 5: Review the management network

UniFi Network → Settings → Networks

Compare the management network and VLAN with the upstream switch-port settings. Menu names can vary by Network version; inspect before making changes.

WORKED INCIDENT

Practical case: A UniFi access point appears offline

Fictional teaching scenario; observations are examples, not captured production output.

Situation

An access point forwards inconsistently and the UniFi console shows it offline.

Investigation sequence

1. Locate the affected device

UniFi Network → Devices

Confirm the site, MAC address, model and displayed status. An offline device may still be forwarding traffic while its management path is unavailable.

2. Inspect the management path

Device details → IP address and uplink

Compare management IP, VLAN and upstream port with the intended topology. An APIPA address indicates that the device did not obtain the expected DHCP address.

3. Review VLAN and link settings

Upstream switch → Ports → Port Manager

Compare native and tagged networks on the uplink with the management VLAN. Inspect settings without applying a new port profile during diagnosis.

4. Review the management network

UniFi Network → Settings → Networks

Compare the management network and VLAN with the upstream switch-port settings. Menu names can vary by Network version; inspect before making changes.

5. Validate the management dependency

Check console reachability and required ports

Use the official UniFi required-ports reference for your deployment. Test only relevant paths; do not broadly open inter-VLAN traffic to make adoption work.

Interpret the findings

An unexpected or missing management address points toward DHCP or VLAN configuration; an expected address with an offline status calls for management-path checks.

Verify the outcome

After the approved network correction, verify the device is online and reachable without resetting or readopting it unnecessarily.

FortiGate HA & system health cheat sheet

Check cluster membership and baseline appliance health.

FortiOS 7.4 inspection reference. Confirm your firmware, privileges and active VDOM; command availability varies by platform.

Walkthrough

Confirm the target device and software release using approved access. Replace angle-bracket placeholders with local values; do not paste placeholders literally. Record the incident time and affected traffic path before collecting output.

Step 1: Inspect cluster members

get system ha status

Record the cluster members, roles and synchronization status without initiating a failover.

Step 2: Inspect resource usage

get system performance status

Capture CPU, memory, uptime and traffic/session indicators during the incident and again after a measured interval. A brief utilization spike and sustained pressure are different findings; compare with the same appliance under normal load.

Step 3: Inspect time synchronization

diagnose sys ntp status

Check time synchronization on the member under investigation; compare time sources and timestamps.

Step 4: Identify firmware

get system status

Record firmware and appliance identity so both members can be compared.

Step 5: Inspect HA diagnostic status

diagnose system ha status

Compare cluster state and member details with the expected primary and secondary roles. Check both units before drawing conclusions about synchronization.

Practical case: The standby firewall shows a health concern

Situation

An HA member has an alert following a maintenance window.

Investigation sequence

1. Inspect cluster members

get system ha status

Record the cluster members, roles and synchronization status without initiating a failover.

2. Inspect time synchronization

diagnose sys ntp status

Check time synchronization on the member under investigation; compare time sources and timestamps.

3. Identify firmware

get system status

Record firmware and appliance identity so both members can be compared.

4. Inspect HA diagnostic status

diagnose system ha status

Read diagnostic HA details and compare member health with the expected cluster state.

Interpret the findings

Compare roles, synchronization and time across members. A mismatch in member state or clock is evidence to investigate; it does not justify an immediate failover.

Verify the outcome

Confirm both members return to the intended cluster state and record the result without forcing a production failover.

Linux system clock synchronization inspection cheat sheet

Inspect system time, synchronization status and the time service on a systemd-based Linux host.

Linux running systemd; timesync-status specifically applies to systemd-timesyncd and may not apply to chrony or other time clients.

Updated 2026-11-13 · Linux · 6 min read

CommandWhat it does
timedatectl statusInspect clock and synchronization status
timedatectl showRead machine-readable clock properties
systemctl status systemd-timesyncd.service --no-pager --fullInspect the timesyncd service
timedatectl timesync-statusInspect timesyncd synchronization details
journalctl -u systemd-timesyncd.service --since "24 hours ago" -n 100 --no-pagerReview recent timesyncd events

Walkthrough

Run on the affected host with authorized journal access. These commands inspect time and service state without changing the clock or synchronization configuration.

Step 1: Inspect clock and synchronization status

timedatectl status

Record local time, universal time, time zone and synchronization indicators. A configured time zone changes display, while synchronization concerns the underlying clock; treat them as separate checks.

Step 2: Read machine-readable clock properties

timedatectl show

Compare the reported time zone and synchronization properties with the intended host role. Property availability varies by systemd release and the active synchronization service.

Step 3: Inspect the timesyncd service

systemctl status systemd-timesyncd.service --no-pager --full

Use this when systemd-timesyncd is the intended client. A host may use chrony or another implementation instead, so an inactive timesyncd service is not automatically a fault.

Step 4: Inspect timesyncd synchronization details

timedatectl timesync-status

When systemd-timesyncd is active, examine the reported server and synchronization details. This command is specific to that service and may fail or be unavailable when another client is in use.

Step 5: Review recent timesyncd events

journalctl -u systemd-timesyncd.service --since "24 hours ago" -n 100 --no-pager

Use this only for a host using systemd-timesyncd. Correlate server or network errors with the incident; log access and retention determine what is visible.

WORKED INCIDENT

Practical case: A host has an incorrect clock

Fictional teaching scenario; observations are examples, not captured production output.

Situation

An application reports time-related errors on a systemd host that should use systemd-timesyncd.

Investigation sequence

1. Inspect clock and synchronization status

timedatectl status

Record the clock, time zone and synchronization status.

2. Inspect the timesyncd service

systemctl status systemd-timesyncd.service --no-pager --full

Confirm the intended time synchronization service and its current state.

3. Inspect timesyncd synchronization details

timedatectl timesync-status

Inspect the selected time server and synchronization details.

4. Review recent timesyncd events

journalctl -u systemd-timesyncd.service --since "24 hours ago" -n 100 --no-pager

Review relevant service messages for the incident window.

Example findings

Illustrative findings: the time zone is correct, but timesyncd is active and reports no successful synchronization with its configured server.

Interpret the findings

The evidence supports investigating time-server reachability or configuration. An active service alone does not prove that the clock is synchronized.

Verify the outcome

After the system owner resolves the approved time path, verify synchronization status and compare timestamps with a trusted reference.

Escalation handoff

Provide host identity, time service, server information and sanitized journal timestamps to the system owner.

FortiGate CLI essentials cheat sheet

The everyday commands for finding your way around a FortiGate.

FortiOS 7.4 inspection reference. Confirm your firmware, privileges and active VDOM; command availability varies by platform.

Updated 2026-11-02 · Fortinet · 6 min read

Walkthrough

Confirm the target device and software release using approved access. Replace angle-bracket placeholders with local values; do not paste placeholders literally. Record the incident time and affected traffic path before collecting output.

Step 1: Identify firmware and device information

get system status

Record the model, firmware and current VDOM so later output is interpreted in the right context.

Step 2: Inspect CPU, memory and uptime

get system performance status

Capture CPU, memory, uptime and traffic/session indicators during the incident and again after a measured interval. A brief utilization spike and sustained pressure are different findings; compare with the same appliance under normal load.

Step 3: Inspect interface information

get system interface

Find the affected interfaces, addresses and administrative state. Compare the WAN and LAN sides with the intended topology.

Step 4: Inspect learned IPv4 neighbors

get system arp

Match the directly connected next hop to its IP and MAC address. Entries can age out when idle; a missing entry alone does not prove a fault. Compare the relevant interface and generate only an approved test before sampling again.

Step 5: Inspect active routes

get router info routing-table all

Identify the best matching destination prefix, next hop and outgoing interface. Check the return path on the peer separately.

Step 6: Inspect high availability state

get system ha status

Check whether the appliance is standalone or part of an HA cluster. Compare member roles and synchronization status with the intended design.

WORKED INCIDENT

Practical case: Users report intermittent internet access

Fictional teaching scenario; observations are examples, not captured production output.

Situation

A branch firewall appears slow during a busy period. Establish its identity, resource state and forwarding path.

Investigation sequence

1. Identify firmware and device information

get system status

Record the model, firmware and current VDOM so later output is interpreted in the right context.

2. Inspect CPU, memory and uptime

get system performance status

Compare CPU and memory with the incident window and a known baseline; capture at least two samples.

3. Inspect interface information

get system interface

Find the affected interfaces, addresses and administrative state. Compare the WAN and LAN sides with the intended topology.

4. Inspect active routes

get router info routing-table all

Identify the best matching destination prefix, next hop and outgoing interface. Check the return path on the peer separately.

Interpret the findings

A high resource reading during the incident suggests load deserves investigation; a missing expected route points toward forwarding. Either result needs correlation before making a change.

Verify the outcome

Record firmware, affected interfaces and a timed baseline; compare a second sample and verify the route and user experience after the approved fix.

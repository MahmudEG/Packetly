Dell PowerEdge iDRAC health checks cheat sheet

Read PowerEdge identity, power state and hardware event history.

iDRAC9 RACADM. Examples use local RACADM installed on the managed host.

Updated 2026-11-02 · Dell · 6 min read

CommandWhat it does
racadm getsysinfoInspect server and iDRAC identity
racadm serveraction powerstatusRead server power state
racadm getselRead the System Event Log
racadm lclog viewRead Lifecycle Controller events
racadm getversionRead controller firmware version

Walkthrough

Use an approved Dell RACADM installation with appropriate privileges. Remote RACADM connection options differ; never place passwords into shared command history.

Step 1: Inspect server and iDRAC identity

racadm getsysinfo

Compare the service tag, model and management information with the asset under investigation. This helps prevent collecting results from the wrong host.

Step 2: Read server power state

racadm serveraction powerstatus

The powerstatus action only reads the state. Do not substitute powercycle, hardreset or powerdown while diagnosing an active production host.

Step 3: Read the System Event Log

racadm getsel

Correlate hardware faults with the reported interruption and verify timestamps. Preserve SEL entries before any log clearing or component replacement.

Step 4: Read Lifecycle Controller events

racadm lclog view

Compare configuration and lifecycle events with the incident timeline. A recent maintenance event can explain a hardware or firmware inventory change.

Step 5: Read controller firmware version

racadm getversion

Compare the controller firmware with the approved server baseline and support information. Version inspection does not apply an update.

Practical case: A PowerEdge server unexpectedly went offline

Situation

A system owner asks whether a hardware event preceded an outage.

Investigation sequence

Interpret the findings

Match the service tag, power status, system events and lifecycle events to the incident time. Reading power status is different from issuing a power action.

Verify the outcome

Preserve the event history and verify system health after approved maintenance; do not reset a running host as a first diagnostic step.

Linux IPv6 host path inspection cheat sheet

Inspect IPv6 addresses, route selection, neighbors and listeners on a Linux host.

Linux with iproute2 and ss. Results depend on the host network namespace.

Updated 2026-11-11 · Linux · 6 min read

CommandWhat it does
ip -6 address showInspect IPv6 addresses
ip -6 route showList IPv6 routes
ip -6 route get 2001:db8::25Inspect route selection for a destination
ip -6 neigh showInspect IPv6 neighbor state
ss -6 -ltnList IPv6 TCP listeners

Walkthrough

Run in the affected host or workload network namespace. Replace 2001:db8::25 with an authorized destination; these commands inspect local state and do not send probes.

Step 1: Inspect IPv6 addresses

ip -6 address show

Compare global and link-local addresses, prefixes and address states with the intended interface. A link-local address is scoped to its link and does not establish global connectivity.

Step 2: List IPv6 routes

ip -6 route show

Identify destination prefixes, default routes and next-hop interfaces. A route being present does not prove that the next hop or remote application is reachable.

Step 3: Inspect route selection for a destination

ip -6 route get 2001:db8::25

Replace the documentation address with the real approved IPv6 destination. Note the selected interface, source address and next hop; check the return path and policy separately.

Step 4: Inspect IPv6 neighbor state

ip -6 neigh show

Compare the selected directly connected next hop with its neighbor state. An absent entry can be normal before traffic; FAILED or INCOMPLETE states are clues to investigate on the local link.

Step 5: List IPv6 TCP listeners

ss -6 -ltn

Compare local IPv6 listener addresses and ports with the intended application. IPv4-mapped behavior can depend on socket and system settings, so verify the actual service configuration.

WORKED INCIDENT

Practical case: An application fails only over IPv6

Fictional teaching scenario; observations are examples, not captured production output.

Situation

Clients receive an IPv6 address for a service but their IPv6 connection fails.

Investigation sequence

1. Inspect IPv6 addresses

ip -6 address show

Confirm the affected host has the expected IPv6 address on the intended interface.

2. List IPv6 routes

ip -6 route show

Inspect the IPv6 routing table for the relevant destination prefix.

3. Inspect route selection for a destination

ip -6 route get 2001:db8::25

Check the selected source address, route and next hop for the service.

4. Inspect IPv6 neighbor state

ip -6 neigh show

Inspect neighbor state for the directly connected next hop.

Example findings

Illustrative findings: the destination route selects the intended interface, but the next-hop neighbor remains INCOMPLETE during the incident.

Interpret the findings

The neighbor state points toward a local-link or peer-resolution investigation in this example. It does not establish a specific switch, firewall or host fault.

Verify the outcome

After the network owner resolves the issue, repeat the route and neighbor checks and test the approved application over IPv6.

Escalation handoff

Provide the host namespace, interface, selected route, next-hop address and timestamped neighbor state to the network owner.

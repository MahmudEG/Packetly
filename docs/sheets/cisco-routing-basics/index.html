Cisco routing basics cheat sheet

Read connected, static, and learned routes with confidence.

Cisco IOS / IOS XE inspection reference. Confirm device model, release and EXEC privileges; switch-specific commands may not exist on routers.

Updated 2026-11-02 · Cisco · 6 min read

CommandWhat it does

Walkthrough

Confirm the target device and software release using approved access. Replace angle-bracket placeholders with local values; do not paste placeholders literally. Record the incident time and affected traffic path before collecting output.

Step 1: Inspect IPv4 routes

show ip route

Locate the destination prefix and note the selected route source, next hop and outgoing interface.

Step 2: Inspect routing protocols

show ip protocols

Identify active routing protocols, advertised networks and known routing sources. Compare the expected protocol and neighbor information with the design. This summary does not prove that a particular destination was installed in the forwarding table.

Step 3: Inspect IPv4 neighbors

show ip arp

If the next hop is directly connected, compare its IP and MAC mapping with the local segment.

Step 4: Inspect interface status

show ip interface brief

Confirm the outgoing interface has the expected address and operational state. An up interface does not prove end-to-end reachability.

Step 5: Inspect the route to a destination

show ip route <destination-ip>

Replace the placeholder with an IPv4 destination. Review the selected prefix, next hop and interface, then check the return route independently.

WORKED INCIDENT

Practical case: A router has a route but traffic still fails

Fictional teaching scenario; observations are examples, not captured production output.

Situation

A routed service is unreachable from one source network.

Investigation sequence

1. Inspect IPv4 routes

show ip route

Locate the destination prefix and note the selected route source, next hop and outgoing interface.

2. Inspect the route to a destination

show ip route <destination-ip>

Substitute the specific destination address and confirm the most-specific matching route.

3. Inspect IPv4 neighbors

show ip arp

If the next hop is directly connected, compare its IP and MAC mapping with the local segment.

4. Inspect interface status

show ip interface brief

Confirm the outgoing interface has the expected address and operational state. An up interface does not prove end-to-end reachability.

Interpret the findings

The most specific route and outgoing interface establish the forward path only. Check next-hop resolution and the destination’s return route separately.

Verify the outcome

Repeat the destination lookup and perform a scoped service test from the affected source after the approved correction.

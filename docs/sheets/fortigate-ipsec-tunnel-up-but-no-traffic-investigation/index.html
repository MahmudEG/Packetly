FortiGate IPsec tunnel up but no traffic investigation cheat sheet

Compare IPsec security associations, traffic counters and routing when a tunnel is up but applications fail.

FortiOS 7.6; command output and available fields depend on appliance, VDOM and tunnel configuration.

Updated 2026-11-23 · Fortinet · 6 min read

Walkthrough

Use authorized read-only access in the correct VDOM. Generate only approved test traffic and do not clear sessions, reset tunnels or change offloading during diagnosis.

Step 1: Record system identity and version

get system status

Capture the FortiOS version and device identity and confirm the relevant VDOM with the administrator. Behavior and diagnostic fields can differ between releases.

Step 2: Inspect tunnel summary

get vpn ipsec tunnel summary

Find the intended tunnel and record its current status. A displayed up state does not prove that application traffic matches the correct selector or returns successfully.

Step 3: Inspect security associations and counters

diagnose vpn tunnel list

Find the intended tunnel and compare selectors, security associations and available encryption and decryption counters. Handle peer addresses and internal networks as sensitive data.

Step 4: Inspect active routes

get router info routing-table all

Compare the destination route and selected tunnel interface with the documented path. A route listing alone cannot establish firewall policy, selector match or remote return routing.

Step 5: Inspect IKE gateway state

diagnose vpn ike gateway list

Record the relevant peer and gateway state and compare it with the tunnel observations. IKE establishment is one part of the path and does not guarantee forwarding.

WORKED INCIDENT

Practical case: An established tunnel cannot reach a remote application

Fictional teaching scenario; observations are examples, not captured production output.

Situation

A branch tunnel shows up after a maintenance window but clients cannot reach a remote service.

Investigation sequence

1. Record system identity and version

get system status

Confirm the FortiGate version, device and VDOM before comparing results.

2. Inspect tunnel summary

get vpn ipsec tunnel summary

Record the affected tunnel state and the time of the user report.

3. Inspect security associations and counters

diagnose vpn tunnel list

Compare selector details and counters before and after approved test traffic.

4. Inspect active routes

get router info routing-table all

Review the active destination route and compare it with the intended tunnel path.

5. Inspect IKE gateway state

diagnose vpn ike gateway list

Record the related IKE gateway state and correlate with remote-side evidence.

Example findings

Illustrative findings: tunnel security associations exist, but the network team confirms that the remote subnet has a route through the wrong interface.

Interpret the findings

A route mismatch is a specific lead in this example. Tunnel state alone cannot establish whether selectors, policy, routing or the remote endpoint is responsible.

Verify the outcome

After the network owner applies an approved route correction, repeat the counter comparison and verify the application from both ends.

Escalation handoff

Share sanitized tunnel identifiers, timestamps, counter deltas and routing evidence with both VPN administrators.

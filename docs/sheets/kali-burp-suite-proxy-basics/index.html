Kali Burp Suite proxy basics

Inspect requests from a local training application with Burp’s built-in browser.

Burp Suite Community or Professional desktop. Proxy inspection works without an automated scanner.

Walkthrough

Start Burp with a temporary project and default settings. Use a local training application or a target you are explicitly authorized to test; keep personal browsing outside Burp’s browser.

Launch the preconfigured test browser

Proxy → Intercept → Open Browser

Open your approved training application in Burp’s browser. This browser is already configured to use Burp’s proxy, avoiding changes to your everyday browser’s proxy and certificate settings.

Allow ordinary browsing while recording

Proxy → Intercept → Intercept is off

Keep interception off while navigating the lab so requests are not paused. HTTP history still records traffic that passes through the proxy.

Inspect a lab request and response

Proxy → HTTP history

Select a request to your training app and compare the method, path, status and response headers. Apply filters to focus on the approved target and avoid collecting unrelated traffic.

Observe a paused request, then release it

Proxy → Intercept → Intercept is on → Forward

Trigger one harmless page request in the lab browser. Inspect it and click Forward without editing. Turn interception off when finished so later requests do not remain unexpectedly paused.

FortiGate session inspection cheat sheet

Connect policy decisions with live traffic sessions.

FortiOS 7.4 inspection reference. Confirm your firmware, privileges and active VDOM; command availability varies by platform.

Updated 2026-11-02 · Fortinet · 6 min read

Walkthrough

Confirm the target device and software release using approved access. Replace angle-bracket placeholders with local values; do not paste placeholders literally. Record the incident time and affected traffic path before collecting output.

Step 1: Inspect session totals

get system session status

Check current session totals and record the sample time. Compare a second sample during the incident with the normal session count for this appliance; a high count alone does not identify which traffic is responsible.

Step 2: Inspect session statistics

diagnose sys session stat

Compare session statistics with an established baseline for this appliance.

Step 3: Inspect session entries

diagnose sys session list

Inspect the relevant source, destination, translated addresses, policy and interfaces. Filter appropriately for your release before listing a large table.

Step 4: Inspect appliance load

get system performance status

Capture CPU, memory, uptime and traffic/session indicators during the incident and again after a measured interval. A brief utilization spike and sustained pressure are different findings; compare with the same appliance under normal load.

Step 5: Check the route alongside session information

get router info routing-table all

Use the active route table to establish the expected egress path. Existing sessions can persist across changes, so record timing before comparing observations.

WORKED INCIDENT

Practical case: A policy was changed but a connection behaves unexpectedly

Fictional teaching scenario; observations are examples, not captured production output.

Situation

A single client continues to see an old behavior after a firewall policy change.

Investigation sequence

1. Inspect session totals

get system session status

Check current session totals and record the sample time. Compare a second sample during the incident with the normal session count for this appliance; a high count alone does not identify which traffic is responsible.

2. Inspect session statistics

diagnose sys session stat

Compare session statistics with an established baseline for this appliance.

3. Inspect session entries

diagnose sys session list

Inspect the relevant source, destination, translated addresses, policy and interfaces. Filter appropriately for your release before listing a large table.

4. Check the route alongside session information

get router info routing-table all

Compare the active route for the same destination; record the time because an existing session may reflect an earlier forwarding decision.

Interpret the findings

Compare the session’s endpoints, interface and timing with the intended policy and route. Existing sessions can outlive a configuration change.

Verify the outcome

Capture the evidence and follow the approved change procedure before clearing any session; retest a new connection afterwards.

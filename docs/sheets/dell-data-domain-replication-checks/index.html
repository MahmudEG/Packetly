Dell Data Domain replication checks cheat sheet

Inspect replication contexts and distinguish idle replication from a stalled copy.

DD OS replication CLI; context type and supported metrics vary by release.

Updated 2026-11-02 · Dell Data Domain · 7 min read

CommandWhat it does
replication show configIdentify configured replication contexts
replication statusInspect replication state
replication show performance rctx://<context-number>Read context throughput
alerts show currentCorrelate replication with active alerts

Walkthrough

Use authorized read access to the source and destination. Identify the replication context and expected schedule before judging lag.

Step 1: Identify configured replication contexts

replication show config

Match the source and destination paths to the protected workload. Configuration alone does not prove an active or healthy transfer.

Step 2: Inspect replication state

replication status

Check the intended context and compare state with expected activity. An idle context can be healthy when there is no new data to transfer.

Step 3: Read context throughput

replication show performance rctx://<context-number>

Replace the placeholder with a real context number from the configuration. Compare repeated samples with the source workload; a single zero sample is not proof of failure.

Step 4: Correlate replication with active alerts

alerts show current

Check both systems for capacity and connectivity-related alerts. Document the context, observed state and incident time before escalating.

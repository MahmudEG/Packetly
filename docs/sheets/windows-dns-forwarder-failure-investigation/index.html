Windows DNS forwarder failure investigation cheat sheet

Compare Windows DNS forwarding configuration and upstream responses when external names fail to resolve.

Windows Server DNS with the DnsServer PowerShell module and authorized administrative read access.

Updated 2026-11-28 · Windows · 6 min read

CommandWhat it does
Get-DnsServerForwarderInspect server forwarders
Get-DnsServerZoneInspect configured zones
Resolve-DnsName example.com -Server 127.0.0.1 -DnsOnlyQuery the local DNS server
Resolve-DnsName example.com -Server 192.0.2.53 -DnsOnlyQuery the configured forwarder directly
Get-WinEvent -LogName "DNS Server" -MaxEvents 30Inspect DNS server events

Walkthrough

Replace example.com and 192.0.2.53 with an approved test name and forwarder address. Queries send DNS traffic and do not change DNS configuration.

Step 1: Inspect server forwarders

Get-DnsServerForwarder

Record forwarder addresses, timeout and root hint fallback settings from the affected DNS server. Conditional forwarders are configured separately.

Step 2: Inspect configured zones

Get-DnsServerZone

Identify whether the queried namespace is locally hosted or uses a conditional forwarder. Choose the correct path before interpreting general forwarder settings.

Step 3: Query the local DNS server

Resolve-DnsName example.com -Server 127.0.0.1 -DnsOnly

Run on the DNS server with an approved name and record the result. Cached answers or root hint fallback mean success does not prove which upstream answered.

Step 4: Query the configured forwarder directly

Resolve-DnsName example.com -Server 192.0.2.53 -DnsOnly

Replace the example address with the approved forwarder and compare responses from the DNS server host. A direct query is a separate test from the server forwarding path.

Step 5: Inspect DNS server events

Get-WinEvent -LogName "DNS Server" -MaxEvents 30

Review recent DNS Server log events and correlate timestamps with failures. Access and event retention affect what this command can show.

WORKED INCIDENT

Practical case: Internal names resolve but external names fail

Fictional teaching scenario; observations are examples, not captured production output.

Situation

Clients can resolve internal records but external lookups time out.

Investigation sequence

1. Inspect server forwarders

Get-DnsServerForwarder

Record the DNS server forwarding settings and intended upstream addresses.

2. Inspect configured zones

Get-DnsServerZone

Check whether the queried namespace has a separate zone or conditional forwarder.

3. Query the local DNS server

Resolve-DnsName example.com -Server 127.0.0.1 -DnsOnly

Query the local DNS server and the configured forwarder from the same host.

4. Query the configured forwarder directly

Resolve-DnsName example.com -Server 192.0.2.53 -DnsOnly

Review relevant DNS server events around the observed failure.

Example findings

Illustrative findings: local queries time out and direct queries to the configured forwarder also fail from the DNS server.

Interpret the findings

The comparison provides a network or upstream lead; it does not by itself identify the device dropping traffic.

Verify the outcome

After the DNS and network owners correct the confirmed issue, retest with an uncached name and a representative client.

Escalation handoff

Share sanitized upstream addresses, query results and event times with the DNS and network teams.

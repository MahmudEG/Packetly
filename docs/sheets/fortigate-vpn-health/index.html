FortiGate VPN health cheat sheet

Inspect IPsec tunnel health and security associations.

FortiOS 7.4 inspection reference. Confirm your firmware, privileges and active VDOM; command availability varies by platform.

Walkthrough

Confirm the target device and software release using approved access. Replace angle-bracket placeholders with local values; do not paste placeholders literally. Record the incident time and affected traffic path before collecting output.

Step 1: Summarize tunnel state

get vpn ipsec tunnel summary

Locate the tunnel by peer or name and record its status and counters.

Step 2: Inspect IPsec tunnel details

diagnose vpn tunnel list

Inspect phase 2 selectors and security associations for the actual source and destination subnets.

Step 3: Inspect IKE gateways

diagnose vpn ike gateway list

Confirm the expected IKE gateway and remote peer; a missing gateway or unexpected peer narrows the problem.

Step 4: Inspect IPsec status

diagnose vpn ipsec status

Inspect IPsec processing statistics and compare two timed samples during an approved test. Global counters may include multiple tunnels; correlate them with the named tunnel details instead of treating them as proof about one connection.

Step 5: Verify routes toward the remote network

get router info routing-table all

A live tunnel needs a route and matching policy as well as an active security association. Compare the selected egress interface with the expected VPN path.

WORKED INCIDENT

Practical case: An IPsec tunnel is up but a service is unreachable

Fictional teaching scenario; observations are examples, not captured production output.

Situation

A branch-to-branch application has stopped working even though a VPN appears present.

Investigation sequence

1. Summarize tunnel state

get vpn ipsec tunnel summary

Choose the named tunnel used by the affected source and destination. Several established tunnels can coexist; a healthy total does not identify this traffic path.

2. Inspect IPsec tunnel details

diagnose vpn tunnel list

Compare association details and counters before and after a controlled request. Record endpoints and timing so the other administrator can find the same exchange.

3. Inspect IKE gateways

diagnose vpn ike gateway list

Use IKE state to distinguish peer negotiation from the data path. An active gateway is useful context but cannot validate delivery to the protected application.

4. Verify routes toward the remote network

get router info routing-table all

Compare the route for the protected destination with the intended tunnel interface. If forwarding chooses another path, resolve that discrepancy before changing negotiation settings.

Example findings

Example observations during an approved test: the intended tunnel has an active IKE gateway and matching IPsec security associations. Transmit counters rise, while receive counters stay unchanged. Another tunnel on the firewall has unrelated bidirectional traffic.

Interpret the findings

This is evidence of a one-way observation on the intended tunnel, not proof that the remote firewall is broken. Ask the peer administrator to match the same test endpoints, time window and selectors. Compare remote receipt, destination service access and return routing. Global IPsec totals cannot replace counters for this specific tunnel.

Verify the outcome

Retest the application from the same authorized source and correlate traffic on both peers. Confirm the intended selectors and service path. A tunnel returning to an established state is insufficient if the original request still receives no response.

Escalation handoff

Include the affected source and destination, collection times, relevant device release, the observations above and the remaining untested boundary. Remove sensitive identifiers before sharing outside the responsible support team.

FortiGate routing & ARP cheat sheet

Follow a packet from its next hop to the routing table.

FortiOS 7.4 inspection reference. Confirm your firmware, privileges and active VDOM; command availability varies by platform.

Updated 2026-11-02 · Fortinet · 6 min read

Walkthrough

Confirm the target device and software release using approved access. Replace angle-bracket placeholders with local values; do not paste placeholders literally. Record the incident time and affected traffic path before collecting output.

Step 1: Inspect active routes

get router info routing-table all

Compare other active routes for the same destination or a more-specific prefix.

Step 2: Resolve local neighbors

get system arp

Match the directly connected next hop to its IP and MAC address. Entries can age out when idle; a missing entry alone does not prove a fault. Compare the relevant interface and generate only an approved test before sampling again.

Step 3: Inspect detailed ARP entries

diagnose ip arp list

Inspect ARP details and the relevant interface; an unresolved neighbor suggests a local link or peer issue, not necessarily a remote routing problem.

Step 4: Inspect kernel routes

diagnose ip route list

Inspect the kernel forwarding entries for the affected destination and compare them with the routing-table output. Note prefix, interface and gateway. Differences require checking the active VDOM and routing context before drawing conclusions.

Step 5: Inspect the route selected for one destination

get router info routing-table details <destination-ip>

Replace the placeholder with the destination address. Compare the selected route, outgoing interface and gateway with the expected forward path.

WORKED INCIDENT

Practical case: Traffic cannot reach a remote subnet

Fictional teaching scenario; observations are examples, not captured production output.

Situation

A client reaches local systems but fails to reach a service on another subnet.

Investigation sequence

1. Inspect the route selected for one destination

get router info routing-table details <destination-ip>

Replace <destination-ip> with the affected destination. Note the chosen prefix, gateway and interface.

2. Inspect active routes

get router info routing-table all

Compare other active routes for the same destination or a more-specific prefix.

3. Resolve local neighbors

get system arp

Find the next-hop address in the ARP table when it is directly connected; absence can mean it has not recently been contacted.

4. Inspect detailed ARP entries

diagnose ip arp list

Inspect ARP details and the relevant interface; an unresolved neighbor suggests a local link or peer issue, not necessarily a remote routing problem.

Interpret the findings

A missing or unexpected route directs attention to routing. A directly connected next hop without a resolved ARP entry points to the local link or neighbor.

Verify the outcome

Repeat the route lookup and neighbor check, then test the approved service in both directions.

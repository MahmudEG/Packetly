Cisco neighbor discovery cheat sheet

Map the devices directly connected to your switch.

Cisco IOS / IOS XE inspection reference. Confirm device model, release and EXEC privileges; switch-specific commands may not exist on routers.

Updated 2026-11-25 · Cisco · 6 min read

Walkthrough

Confirm the target device and software release using approved access. Replace angle-bracket placeholders with local values; do not paste placeholders literally. Record the incident time and affected traffic path before collecting output.

Step 1: List Cisco discovery neighbors

show cdp neighbors

Identify the local uplink and advertised Cisco neighbor on that port.

Step 2: Inspect neighbor details

show cdp neighbors detail

Inspect neighbor details, including remote port and device identity, and compare with the topology record.

Step 3: List LLDP neighbors

show lldp neighbors

Check LLDP where enabled on both sides; a missing LLDP entry can reflect configuration or peer support.

Step 4: Inspect LLDP details

show lldp neighbors detail

Compare the remote chassis identity and port ID with the local uplink and cabling record. LLDP advertisements describe what the neighbor reports; stale entries or disabled discovery can complicate interpretation, so confirm the physical path separately.

Step 5: Map port descriptions to the topology

show interfaces description

Compare interface descriptions with discovered neighbors and the physical cabling plan. Descriptions are manually maintained and can be stale.

WORKED INCIDENT

Practical case: The switch uplink connects to an unexpected device

Fictional teaching scenario; observations are examples, not captured production output.

Situation

A topology diagram and port label disagree about an uplink.

Investigation sequence

1. List Cisco discovery neighbors

show cdp neighbors

Start with the local interface carrying the uplink. A neighbor elsewhere on the switch cannot validate this cable merely because its device name looks familiar.

2. Inspect neighbor details

show cdp neighbors detail

Compare the advertised identity and remote port with the existing patch record. Capture collection time because entries can remain briefly after a topology change.

3. List LLDP neighbors

show lldp neighbors

Treat LLDP as a separate observation. Confirm whether it is enabled and supported before interpreting the absence of an advertisement as a physical failure.

4. Map port descriptions to the topology

show interfaces description

Compare the manually maintained description with the discovery and cable evidence. Request physical confirmation if the sources disagree; do not silently choose the most convenient name.

Example findings

Example observations: the uplink description says SW-B port 1. CDP details on that local uplink advertise SW-C port 24; the physical patch record also points to SW-C. LLDP has no entry on that link.

Interpret the findings

Two independent observations support correcting the inventory, but neither the interface description nor an advertisement is an authoritative statement of ownership. Confirm the physical path and inventory identity before editing records. The absent LLDP entry does not contradict a CDP neighbor: protocol support and enablement can differ between peers.

Verify the outcome

After the physical path is confirmed, update the approved cabling/inventory record and any authorized interface description. Recheck the same local and remote port identifiers. Keep an unexplained identity discrepancy open rather than inventing an intermediate switch.

Escalation handoff

Include the affected source and destination, collection times, relevant device release, the observations above and the remaining untested boundary. Remove sensitive identifiers before sharing outside the responsible support team.

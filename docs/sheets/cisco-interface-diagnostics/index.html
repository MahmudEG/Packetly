Cisco interface diagnostics cheat sheet

Find link failures and read the counters that matter.

Cisco IOS / IOS XE inspection reference. Confirm device model, release and EXEC privileges; switch-specific commands may not exist on routers.

Updated 2026-11-02 · Cisco · 6 min read

CommandWhat it does
show ip interface briefSummarize interface state
show interfaces statusInspect switch port status
show interfaces counters errorsInspect switch errors
show interfaces descriptionInspect configured descriptions
show interfacesInspect detailed interface state

Walkthrough

Confirm the target device and software release using approved access. Replace angle-bracket placeholders with local values; do not paste placeholders literally. Record the incident time and affected traffic path before collecting output.

Step 1: Summarize interface state

show ip interface brief

Identify the affected interface and compare IP address, administrative state and protocol.

Step 2: Inspect switch port status

show interfaces status

Check switch-port state and negotiated link attributes on the relevant port.

Step 3: Inspect switch errors

show interfaces counters errors

Capture error counters twice with timestamps; rising CRC or input errors are stronger evidence than one old nonzero value.

Step 4: Inspect configured descriptions

show interfaces description

Use descriptions to identify the intended connection, then verify the peer and cabling because labels can be stale.

Step 5: Inspect detailed interface state

show interfaces

Read input errors, output errors, drops and link transitions for the affected port. Compare two samples because counters may include old events.

WORKED INCIDENT

Practical case: A switch port drops connectivity intermittently

Fictional teaching scenario; observations are examples, not captured production output.

Situation

One wired client disconnects while nearby clients remain online.

Investigation sequence

1. Summarize interface state

show ip interface brief

Identify the affected interface and compare IP address, administrative state and protocol.

2. Inspect switch port status

show interfaces status

Check switch-port state and negotiated link attributes on the relevant port.

3. Inspect switch errors

show interfaces counters errors

Capture error counters twice with timestamps; rising CRC or input errors are stronger evidence than one old nonzero value.

4. Inspect configured descriptions

show interfaces description

Use descriptions to identify the intended connection, then verify the peer and cabling because labels can be stale.

Interpret the findings

A down link indicates a physical or peer issue; increasing errors while the link is up suggest a link-quality or negotiation issue. Compare two samples.

Verify the outcome

After the approved repair, check link state and error trends again and have the user retest the application.

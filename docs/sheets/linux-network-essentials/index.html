Linux network essentials cheat sheet

A small toolkit for inspecting a Linux host’s network.

Linux with iproute2. Some process and interface details require elevated read privileges.

Updated 2026-11-02 · Linux · 6 min read

Walkthrough

Confirm the target device and software release using approved access. Replace angle-bracket placeholders with local values; do not paste placeholders literally. Record the incident time and affected traffic path before collecting output.

Step 1: Inspect interface addresses

ip address show

Identify the interface carrying the affected traffic and compare its address and prefix with the intended subnet.

Step 2: Inspect routing table

ip route show

Find the default or more-specific route and note its gateway and source interface.

Step 3: Inspect neighbors

ip neigh show

Inspect the neighbor state for a directly connected gateway; incomplete or failed resolution suggests a local path issue.

Step 4: Inspect listening TCP and UDP sockets

ss -tuln

Read the local address and port for TCP listeners and bound UDP sockets. A loopback-only listener cannot accept remote traffic. UDP does not establish a TCP-style listening session, and a bound socket alone does not prove the application is responding.

Step 5: Inspect interface counters

ip -s link show

Compare errors and drops on the affected link over time. The counters describe interface activity and do not independently identify an application fault.

WORKED INCIDENT

Practical case: A Linux server cannot reach its gateway

Fictional teaching scenario; observations are examples, not captured production output.

Situation

A server has lost connectivity after a network change.

Investigation sequence

1. Inspect interface addresses

ip address show

Identify the interface carrying the affected traffic and compare its address and prefix with the intended subnet.

2. Inspect routing table

ip route show

Find the default or more-specific route and note its gateway and source interface.

3. Inspect neighbors

ip neigh show

Inspect the neighbor state for a directly connected gateway; incomplete or failed resolution suggests a local path issue.

4. Inspect interface counters

ip -s link show

Compare link errors and drops across two timed samples to see whether counters are increasing.

Interpret the findings

Verify the intended address and route first. A missing or incomplete neighbor entry for a directly connected gateway suggests local link or neighbor resolution trouble.

Verify the outcome

Repeat the address, route and neighbor checks and test the approved destination after the network issue is corrected.

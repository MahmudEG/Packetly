Proxmox Backup Server verification failure investigation cheat sheet

Investigate a failed backup verification using datastore tasks and snapshot status before planning recovery.

Walkthrough

This is a read-only review procedure. Verification and restore jobs consume resources and must follow the backup owner’s approved maintenance and recovery process.

Step 1: Open the task history for the affected datastore

Locate the failed verification task

Identify the verification job and record its time, result and datastore. A failed task can affect one snapshot or several, so inspect its actual scope.

Step 2: Open the failed task and inspect the detailed log

Read the task log

Record affected snapshot identifiers and error messages. Preserve the complete log for the backup owner and avoid publishing internal hostnames or repository details.

Step 3: Open the datastore content and locate the affected snapshots

Inspect snapshot verification status

Compare snapshot dates and verification results. A successful backup task and a successful verification are separate observations with different meanings.

Step 4: Review datastore capacity and storage alerts with the storage owner

Compare related storage health

Correlate the task time with available capacity, hardware or filesystem alerts. A storage warning is a lead, not proof that every backup is corrupt.

Step 5: Identify an approved isolated restore target and recovery point

Plan a recovery test

Coordinate a test restore with the recovery owner. Verification checks backup data, but a successful verification alone does not prove that the application can be recovered and operated.

WORKED INCIDENT

Practical case: A nightly backup verification reports an error

Situation

A backup operator sees a failed verification task for a critical virtual machine backup.

Investigation sequence

1. Open the task history for the affected datastore

Locate the failed verification task

Identify the datastore and failed verification task in the task history.

2. Open the failed task and inspect the detailed log

Read the task log

Read the complete task log and record the affected snapshot identifiers.

3. Open the datastore content and locate the affected snapshots

Inspect snapshot verification status

Compare the verification state and dates of the affected and neighboring snapshots.

4. Review datastore capacity and storage alerts with the storage owner

Compare related storage health

Correlate storage health alerts with the time of the verification failure.

5. Identify an approved isolated restore target and recovery point

Plan a recovery test

Ask the recovery owner to select an isolated test target and a suitable recovery point.

Example findings

Illustrative findings: verification identifies an unreadable chunk for one snapshot, and storage monitoring reports an error for the same datastore.

Interpret the findings

The task log identifies a specific affected recovery point and the storage alert provides a separate investigation lead. Neither observation proves the status of every snapshot.

Verify the outcome

After storage remediation, follow the owner’s verification and isolated restore procedures and document the outcome and recovery point.

Escalation handoff

Share the task log, affected snapshots and storage alerts with the backup and storage teams without exposing credentials.

Docker Compose environment interpolation investigation cheat sheet

Inspect Compose variable interpolation when a service receives an unexpected configuration value.

Docker Compose plugin on Linux; run from the same project directory and context used for deployment.

Updated 2026-11-25 · Docker · 6 min read

Walkthrough

Rendered configuration and interpolation values can expose passwords. Inspect locally in a protected session and never publish raw output.

Step 1: Identify Compose version

docker compose version

Record the installed plugin version so option availability and interpolation behavior can be checked against the correct documentation.

Step 2: Validate the Compose model

docker compose config --quiet

Validate the resolved project configuration without printing the model. This does not prove that an existing container was created with the current values.

Step 3: List interpolation variables

docker compose config --variables

Inspect declared variables and defaults for the project. Treat output as sensitive because defaults may contain configuration values.

Step 4: Inspect interpolation inputs

docker compose config --environment

Review the values Compose uses for interpolation in a protected session. Shell variables and environment files can have different precedence; redact secrets.

Step 5: Inspect current project containers

docker compose ps

Identify the actual service and container state. A running container may still reflect an earlier configuration until recreated through an approved deployment.

Practical case: A service uses the wrong image tag

Situation

An operator changes an environment file but the running service still uses the previous image.

Investigation sequence

1. Identify Compose version

docker compose version

Record the Compose version and confirm the project directory.

2. Validate the Compose model

docker compose config --quiet

Validate the current model without exposing the full configuration.

3. List interpolation variables

docker compose config --variables

Inspect the interpolation variable names and protected input values.

4. Inspect interpolation inputs

docker compose config --environment

Compare the current project containers with the approved deployment record.

Example findings

Illustrative findings: a shell variable overrides the edited environment file, and the running container was created before the change.

Interpret the findings

The input precedence and container creation history explain this example; editing a file alone does not update an existing container.

Verify the outcome

After an approved deployment with corrected inputs, verify the rendered model and running image through the normal release process.

Escalation handoff

Share the variable name, source and sanitized deployment evidence without exposing secrets.

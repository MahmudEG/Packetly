Entra ID sign-in investigation

Review recent sign-ins and distinguish authentication from policy failures.

Microsoft Entra admin center sign-in logs. Labels can vary by portal release.

Walkthrough

Use at least an appropriate log-reading role such as Reports Reader. Available history and fields depend on licensing and retention.

Open sign-in activity

Entra ID → Monitoring & health → Sign-in logs

Select the affected tenant first. Limit the time window and user so you do not mistake unrelated background sign-ins for the reported attempt.

Isolate the reported attempt

Filter by user, date and status

Record the timestamp and time zone, application and correlation ID. Ask the user for the precise attempt time if multiple failures exist.

Read the authentication outcome

Open event → Basic info / Authentication details

Compare the failure reason with individual authentication steps. A successful first factor may still be followed by an MFA or policy failure.

Inspect applied policy results

Open event → Conditional Access

Inspect each evaluated policy and grant control. Report-only results do not enforce a block; do not disable policies as a diagnostic shortcut.

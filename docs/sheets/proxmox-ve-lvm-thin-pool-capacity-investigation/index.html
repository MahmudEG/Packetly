Proxmox VE LVM thin pool capacity investigation cheat sheet

Compare Proxmox storage status with LVM thin pool data and metadata usage before a virtual disk runs out of space.

Proxmox VE 8 or 9 using a local LVM-thin storage backend; other backends require different capacity checks.

Updated 2026-11-23 · Proxmox · 6 min read

Walkthrough

Use authorized read access on the node hosting the local pool. Do not resize, remove volumes or run filesystem repair commands during evidence collection.

Step 1: Identify the Proxmox release

pveversion

Record the node identity and installed Proxmox release so the storage backend and documentation can be interpreted in context.

Step 2: Inspect Proxmox storage capacity

pvesm status

Record the affected storage ID, type and usage on the relevant node. Storage pools and the root filesystem can report different capacity because they are distinct allocations.

Step 3: Inspect thin pool usage

lvs -a -o lv_name,vg_name,lv_attr,lv_size,data_percent,metadata_percent

Find the correct pool and record data and metadata utilization separately. Thin provisioned virtual disk sizes can exceed currently allocated physical data capacity.

Step 4: Inspect volume group free capacity

vgs

Record the volume group size and free extents. Available volume group capacity does not automatically enlarge a thin pool and must be reviewed with the storage owner.

Step 5: Compare mounted filesystem capacity

df -h

Inspect filesystem usage for comparison with the affected pool. A healthy root filesystem does not prove that a separate LVM-thin data or metadata pool has free space.

WORKED INCIDENT

Practical case: Virtual disks report low storage while root has space

Fictional teaching scenario; observations are examples, not captured production output.

Situation

An operator sees a nearly full Proxmox storage pool even though the root filesystem has substantial free space.

Investigation sequence

1. Identify the Proxmox release

pveversion

Identify the Proxmox node and release that owns the affected local storage.

2. Inspect Proxmox storage capacity

pvesm status

Locate the affected storage ID and its backend in the Proxmox status output.

3. Inspect thin pool usage

lvs -a -o lv_name,vg_name,lv_attr,lv_size,data_percent,metadata_percent

Inspect the corresponding thin pool data and metadata percentages.

4. Inspect volume group free capacity

vgs

Review free extents in the volume group and compare root filesystem usage.

Example findings

Illustrative findings: the root filesystem has free space, while the local thin pool data usage is near capacity and the volume group has limited free extents.

Interpret the findings

The measurements identify a pool-specific capacity problem. Free space in a separate filesystem cannot automatically satisfy thin pool writes.

Verify the outcome

After the storage owner completes an approved capacity plan, recheck pool data and metadata utilization and monitor guest health.

Escalation handoff

Provide the storage ID, node, sanitized pool usage and volume group capacity to the virtualization and storage teams.

Kali Nmap discovery essentials cheat sheet

Discover a lab host’s exposed TCP services and interpret scan states.

Kali Linux with Nmap 7.x. Examples use one explicitly authorized lab host.

Updated 2026-11-02 · Kali Linux · 6 min read

CommandWhat it does
nmap --versionCheck the installed scanner version
nmap -sn <lab-ip>Check host discovery responses
nmap -sT -p 22,80,443 <lab-ip>Inspect three selected TCP ports
nmap -sT -sV -p 22,80,443 <lab-ip>Identify services on selected ports
nmap -sT -p 443 --reason <lab-ip>Show the reason for the reported port state

Walkthrough

Replace <lab-ip> with the address of a system you own or have permission to assess. These commands send network probes; agree on scope before scanning.

Step 1: Check the installed scanner version

nmap --version

Record the Nmap version and available libraries before following examples. Package versions can differ between Kali installations and rolling updates.

Step 2: Check host discovery responses

nmap -sn <lab-ip>

Replace the placeholder with one approved target. Host discovery does not perform a port scan. A host marked down may simply block the discovery probes; it is not proof the machine is absent.

Step 3: Inspect three selected TCP ports

nmap -sT -p 22,80,443 <lab-ip>

This TCP connect scan checks only the listed ports. Open means a connection was accepted; closed and filtered have different meanings. Results reflect this source host and observation time.

Step 4: Identify services on selected ports

nmap -sT -sV -p 22,80,443 <lab-ip>

Service detection sends additional application probes. Treat product and version matches as evidence to verify with the service owner, not a definitive vulnerability finding.

Step 5: Show the reason for the reported port state

nmap -sT -p 443 --reason <lab-ip>

Replace the placeholder with a single authorized host. Compare the reason and timing with firewall logs; a filtered state is not proof of a specific filtering device.

Practical case: Validate a lab host’s exposed ports

Situation

A lab owner asks which of three known TCP services are reachable from an approved test machine.

Interpret the findings

Confirm the authorized target and compare host discovery with a bounded connect scan. A filtered port is not proof of which firewall or host caused the filtering.

Verify the outcome

Repeat the same limited scan after the approved change and compare port states and reasons with the original results.

Windows network troubleshooting cheat sheet

Inspect addressing, DNS resolution and TCP reachability with PowerShell.

Windows 10/11 and Windows Server with NetTCPIP and DnsClient modules.

Updated 2026-11-02 · Windows · 6 min read

Walkthrough

Open PowerShell on the affected host. Replace server.example.com with an approved test host; TCP tests send probes.

Step 1: Inspect addresses and gateways

Get-NetIPConfiguration

Find the adapter carrying the affected traffic. Compare its address, default gateway and DNS servers with the intended subnet. Disconnected adapters may appear alongside the active one.

Step 2: Inspect adapter state and link speed

Get-NetAdapter

Match the interface name to the physical or virtual adapter. A disconnected interface points to a link or virtual-switch issue before DNS becomes relevant.

Step 3: Resolve a host name

Resolve-DnsName server.example.com

Replace the example name with your target. Check the answer and record whether the response is NXDOMAIN, a timeout or an unexpected address; these indicate different failure paths.

Step 4: Test a specific TCP service

Test-NetConnection server.example.com -Port 443

Check TcpTestSucceeded and the selected source address. A successful test confirms a TCP connection, not application authentication or TLS correctness.

Step 5: List configured DNS servers by interface

Get-DnsClientServerAddress

Match the server addresses to the adapter used by the affected connection. A configured server can still be unreachable or return an unexpected answer.

WORKED INCIDENT

Practical case: A Windows workstation cannot open an internal site

Fictional teaching scenario; observations are examples, not captured production output.

Situation

The browser fails to reach an internal HTTPS application, while the user is connected to the network.

Investigation sequence

1. Inspect adapter state and link speed

Get-NetAdapter

Match the interface name to the physical or virtual adapter. A disconnected interface points to a link or virtual-switch issue before DNS becomes relevant.

2. Inspect addresses and gateways

Get-NetIPConfiguration

3. Resolve a host name

4. Test a specific TCP service

Test-NetConnection server.example.com -Port 443

Check TcpTestSucceeded and the selected source address. A successful test confirms a TCP connection, not application authentication or TLS correctness.

5. List configured DNS servers by interface

Get-DnsClientServerAddress

Interpret the findings

A failed DNS lookup differs from successful name resolution followed by a failed TCP connection. Compare the selected adapter and DNS server with the expected configuration.

Verify the outcome

Repeat name resolution and the TCP 443 test using the intended service name, then retest in the application.

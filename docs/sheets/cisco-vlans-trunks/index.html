Cisco VLANs & trunks cheat sheet

Understand access VLANs, tagged links, and Layer 2 boundaries.

Cisco IOS / IOS XE inspection reference. Confirm device model, release and EXEC privileges; switch-specific commands may not exist on routers.

Updated 2026-11-02 · Cisco · 6 min read

CommandWhat it does

Walkthrough

Confirm the target device and software release using approved access. Replace angle-bracket placeholders with local values; do not paste placeholders literally. Record the incident time and affected traffic path before collecting output.

Step 1: Inspect VLAN membership

show vlan brief

Find the endpoint access port and its assigned VLAN. A defined VLAN alone does not prove that it reaches the gateway.

Step 2: Inspect trunk status

show interfaces trunk

On both ends of the uplink compare trunk state and the allowed and active VLAN lists.

Step 3: Inspect switchport settings

show interfaces switchport

Inspect the access port and uplink switchport mode, including native VLAN where relevant.

Step 4: Inspect spanning tree state

show spanning-tree

Identify the root bridge, VLAN or instance and the uplink port roles. A blocked alternate path can be correct loop prevention. Investigate an unexpected root or role against the topology rather than trying to force a blocked port into forwarding.

Step 5: Inspect learned MAC addresses

show mac address-table

Compare the learned VLAN and port against the endpoint location. An inactive endpoint may age out, so an absent entry is not conclusive by itself.

WORKED INCIDENT

Practical case: A new VLAN works locally but not across switches

Fictional teaching scenario; observations are examples, not captured production output.

Situation

A workstation and gateway are on different switches and the VLAN does not pass the uplink.

Investigation sequence

1. Inspect VLAN membership

show vlan brief

Find the endpoint access port and its assigned VLAN. A defined VLAN alone does not prove that it reaches the gateway.

2. Inspect trunk status

show interfaces trunk

On both ends of the uplink compare trunk state and the allowed and active VLAN lists.

3. Inspect switchport settings

show interfaces switchport

Inspect the access port and uplink switchport mode, including native VLAN where relevant.

4. Inspect learned MAC addresses

show mac address-table

Look for the endpoint MAC in the correct VLAN and note the learned port; an inactive endpoint can age out.

Interpret the findings

Check that the access port is in the intended VLAN and the VLAN is allowed and active on the trunk. MAC learning on the expected port helps localize the path.

Verify the outcome

Recheck both ends of the trunk, learned MAC addresses and the gateway test after the approved configuration change.

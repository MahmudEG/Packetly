HPE Aruba CX switching essentials cheat sheet

Inspect AOS-CX switch interfaces and VLANs with platform-specific commands.

HPE Aruba Networking AOS-CX 10.13. Not Comware or ArubaOS-Switch.

Updated 2026-11-02 · HPE · 6 min read

CommandWhat it does

Walkthrough

Use a switch account permitted to run show commands. Port naming and command availability depend on the CX model.

Step 1: Identify the CX software release

show version

Confirm that the device runs AOS-CX. Do not reuse these commands unmodified on Comware or AOS-S switches.

Step 2: Inspect interface summary

show interface brief

Use the displayed interface names to find the uplink or endpoint port. Compare administrative state, link state and speed with expected operation.

Step 3: Inspect configured VLANs

show vlan

Compare VLAN IDs and membership with both ends of each trunk. A VLAN being defined does not prove that it is carried on the affected link.

Step 4: Inspect discovered neighbors

show lldp neighbor-info

Map local ports to remote devices and ports. LLDP requires compatible configuration on the peer, so absent discovery is not itself proof of a broken link.

Step 5: Inspect switch system information

show system

Record the system identity and compare the hardware and software context with the intended switch. Command output varies with AOS-CX platform and release.

Practical case: An Aruba CX switch port is up but the endpoint is isolated

Situation

A device connects physically but cannot reach its expected VLAN.

Investigation sequence

1. Identify the CX software release

show version

Confirm that the device runs AOS-CX. Do not reuse these commands unmodified on Comware or AOS-S switches.

2. Inspect interface summary

3. Inspect configured VLANs

4. Inspect discovered neighbors

5. Inspect switch system information

show system

Record the system identity and compare the hardware and software context with the intended switch. Command output varies with AOS-CX platform and release.

Interpret the findings

Confirm AOS-CX and inspect the port, VLAN membership and neighbor path. A VLAN existing on the switch does not prove it is carried across the uplink.

Verify the outcome

Verify port and VLAN state at both ends and retest the endpoint after the approved change.
